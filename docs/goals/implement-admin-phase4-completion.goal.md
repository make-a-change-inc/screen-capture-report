# GOAL: テナントデータ管理とパスワード保護を完成する

## Objective

元仕様にあるテナント単位のデータ出力・削除を、安全な申請・保持・証跡フローに統合し、管理ユーザーの初期パスワードを変更可能にして保存ハッシュを強化する。

## Requirements

1. Ownerだけがテナントの企業設定、管理者公開属性、従業員、端末、レポート本文、同意、監査をJSONとして出力できる。
2. 出力にパスワードハッシュ、MFA秘密鍵、端末トークン、Webhook URLなどの秘密情報を含めない。
3. テナント削除はプライバシー申請の登録、処理開始、リーガルホールド確認、不可逆操作の確認を経て実行する。
4. テナント削除はレポート・版・集計・従業員・端末・運用メタデータ・分類・配信設定を削除し、管理アカウントと削除証跡は監査のため残す。
5. 新規管理ユーザーのパスワードはPBKDF2-SHA256（ランダムsalt、十分な反復回数）で保存し、旧SHA-256ハッシュは正しいログイン時に自動移行する。
6. 各ユーザーは現在のパスワード確認付きでパスワードを変更でき、変更時に自分の他セッションを失効する。

## Acceptance

- Ownerの出力は復号済みレポートを含む一方で秘密情報を含まず、Managerは403になる。
- テナント削除後に業務データ件数が0となり、管理ユーザーと削除証跡は残る。
- 旧パスワードは変更後に失敗し、新パスワードでログインできる。
- Workerテスト、チェック、ビルド、Cloudflare dry-run、本番未認証401が成功する。
