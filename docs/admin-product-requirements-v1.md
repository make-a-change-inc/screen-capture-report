# WORK VISIBILITY AI 管理機能 要件定義 v1

## 1. 目的

端末から同期された確定済み週次管理レポートを、監視ではなく業務改善とAI投資判断に利用できる管理機能として提供する。本書は `apps/windows/docs/product-concept-and-admin-requirements.md`（Draft 0.1）を、現行POCのデータ境界と本番運用上の安全性に合わせて確定した実装要件である。

## 2. Grill-meで確定した判断

- 「元仕様すべて」は一括で画面だけを作る意味にはしない。Mustを本物のデータと権限制御で完成させ、Should/Laterは依存基盤ごと段階実装する。
- 管理サーバーへ生画像、ウィンドウタイトル、本人日報、詳細作業ログを送らない。個人ランキングも表示しない。
- 従業員管理は当面読み取り専用とする。作成・編集・削除は表示しない。
- AI削減時間は実績ではなく暫定試算と明示し、係数、対象期間、対象人数、サンプル数を表示する。「その他」「未分類」は候補から除外し、品質課題として集計する。
- レポートは現行契約で取得できる「確定済み管理者向け週次レポート」から開始する。存在しない日報・配信・レビュー状態を捏造しない。
- パスワードをWeb Storageへ保存しない。ログイン後はHttpOnly Cookieの短命なサーバーセッションを使い、ログアウト時に失効させる。
- 企業コードだけの自己端末登録は許可しない。管理者が発行した端末トークン／登録ファイルを利用する。
- 日時は日本語表示とし、組織タイムゾーンを設定可能にする。初期値は `Asia/Tokyo`、週開始は月曜日。

## 3. 今回のリリース（Phase 1）

### 3.1 共通

- 日本語のサイドナビゲーションとレスポンシブなモバイルナビ
- ローディング、空、絞り込み結果なし、認証切れ、取得失敗、部分データを区別
- キーボード操作、フォーカス表示、`aria-current`、`aria-live`、表見出しを提供
- 全APIをテナントスコープで制限し、ID直指定でも他社データを返さない

### 3.2 経営ダッシュボード

- 期間・部署フィルター
- 実測時間、暫定削減見込み、対象従業員、同期レポート数
- 前週比較、カテゴリ構成、最大12週の推移
- AI化候補上位3件、データ品質、要対応事項

### 3.3 業務分析

- カテゴリ別の総時間、構成比、一人当たり時間
- 部署別比較、週次推移
- CSV出力（集計値のみ）
- 曜日・時間帯・職種・雇用区分は、集計データ契約が追加されるまで表示しない

### 3.4 AI化候補

- 対象カテゴリ・部署・人数・実測時間・暫定自動化率・削減見込み
- 推奨手段、算出式、根拠期間、サンプル数、注意事項
- 候補は実測カテゴリから算出し、未分類系カテゴリを除外
- ステータス変更、担当者、ROI、PoC管理はPhase 2で永続化後に提供

### 3.5 レポート

- 確定済み週次管理レポートの一覧、氏名・部署・期間による絞り込み
- 対象、版、受信日時、実測値を表示
- 暗号化本文をテナント確認後に復号し、sandbox付き詳細画面で閲覧
- レポート本文を監査ログやCSVへ含めない

### 3.6 従業員・端末

- 従業員は氏名、部署、状態、端末数、最終同期、最新レポートの読み取り専用一覧
- 端末は端末名、利用者、版、最終通信、サーバー時刻基準の状態を表示
- 端末状態は「正常」「要確認」「未同期」「無効」を文言で表示し、色だけに依存しない

### 3.7 分類・品質、プライバシー、監査、組織設定

- 構造化メトリクス率、HTML復元率、カテゴリなし、未分類率を表示
- 現在の収集境界、暗号化、保持期間を表示
- テナント別のレポート保持日数、監査保持日数、タイムゾーン、週開始を設定・監査
- 管理者のログイン、ログアウト、レポート閲覧、CSV出力、設定変更、端末発行をテナント別監査一覧で確認
- 監査メタデータへ秘密情報・本文を保存しない

## 4. セキュリティ受け入れ条件

1. ログイン成功時のみCookieセッションを発行し、パスワードをブラウザ保存しない。
2. セッションはHttpOnly、Secure、SameSite=Strict、期限付きで、ログアウト後は再利用できない。
3. 状態変更APIは同一オリジンとCSRFトークンを検証する。
4. すべての一覧・詳細APIで会社IDをSQL条件に含める。
5. 未認証の端末自己登録は既定で拒否する。
6. レポート本文はAES-GCM暗号化を維持し、iframeはsandboxとCSPで隔離する。
7. 保持期限処理は会社関連行を含めて削除し、結果を監査する。

## 5. Phase 2 / 3

### Phase 2

- レポート版履歴、レビュー・確定・配信状態
- AI候補の状態、判断理由、担当者、導入前後比較
- 分類ルールの版管理、低信頼データ、訂正履歴、再集計
- 同意、除外ポリシー、削除依頼、リーガルホールド
- 端末heartbeatの詳細指標とWindowsアプリからの匿名集計送信

### Phase 3

- 複数管理ユーザー、Owner／Manager／Auditorの組織スコープRBAC
- SSO、MFA、IdP連携
- PDF、メール、Slack／Teams配信
- HRマスター連携、多言語、データレジデンシー

これらは外部認証・配信資格情報、法務・労務判断、追加データ契約が必要なため、設定なしで動作したように見せない。

## 6. 完了条件

- Phase 1の各ページがCloudflare D1の同一テナント実データで動作する。
- テナント分離、認証失効、レポート復号、保持期限、XSS隔離の自動テストが通る。
- Workerの検証と本番デプロイが成功し、本番でログイン・主要ページ・APIをスモーク確認できる。
- 未取得データを0または正常と誤表示せず、欠損理由を表示する。
