# WORK VISIBILITY AI コンセプト・管理画面要件

> Status: Draft 0.1  
> 作成日: 2026-07-21  
> 入力: 白石さん作成LP、LPファーストビュー画像、既存POC仕様  
> 用途: プロダクト方針の共有、管理画面の企画・設計・開発の土台

## 1. この文書の目的

LPで表現された価値提案と設計思想をプロダクトコンセプトとして整理し、そこから管理画面に必要な要件を導出する。

管理画面はスクリーンショットを監視する画面ではない。従業員の仕事を定量化し、本人の振り返り、マネージャーの業務改善、経営のAI投資判断につなげるための「意思決定画面」として設計する。

## 2. プロダクトコンセプト

### 2.1 一言で表すと

**勘ではなく、事実で、AI化する。**

従業員PCの作業状況を約1分間隔で記録し、AIが作業内容を分類・集計することで、「誰が・何に・何時間を使っているか」を可視化する。実測データをもとに、AI化・自動化すべき業務と削減可能時間を継続的に提案する。

### 2.2 解決する課題

- AI化の対象業務が、実測ではなく印象や声の大きさで決まっている
- 自己申告の日報や工数入力は粒度が粗く、記入負荷と記憶誤差がある
- AIツール導入前に、対象業務の量と期待効果を定量評価できない
- 導入後も、削減時間や業務変化を継続的に検証しづらい
- 経営、マネージャー、本人で必要な情報の粒度と目的が異なる

### 2.3 提供価値

| 対象 | 欲しい答え | 提供価値 |
|---|---|---|
| 本人 | 今日、何に時間を使ったか | 入力不要の自動日報と振り返り |
| マネージャー | チームの時間はどこに使われ、何を改善できるか | 業務配分、偏り、反復業務の可視化 |
| 経営者 | どの業務からAI投資すべきか | 削減時間・効果試算つきの優先順位 |
| 導入・運用管理者 | 正しく安全に記録・分析できているか | 端末、同意、分類、配信、監査の運用管理 |

### 2.4 プロダクトの基本フロー

1. **Record:** Windows PCが約1分ごとに画面を記録する
2. **Analyze:** AIが作業内容を判定し、業務カテゴリと時間に変換する
3. **Aggregate:** 人・部署・業務・期間別に定量集計する
4. **Propose:** AI化候補、削減可能時間、推奨施策を提示する
5. **Deliver:** 本人・マネージャー・経営者へ、それぞれに適したレポートを届ける
6. **Improve:** 人による確認結果や施策実施後の変化を次の分析へ反映する

### 2.5 納品物

- 本人への自動日報
- 業務時間の実測データ
- 週次のAI化提案レポート
- 本人・マネージャー・経営者の3視点のAIレポート

### 2.6 設計原則

#### 監視ではなく、可視化

評価や処罰を目的に個人の画面を常時のぞく機能にはしない。収集したデータは、まず本人の振り返りと業務改善に使う。

#### 減らすのは人ではなく業務

個人の勤務態度をランク付けするのではなく、反復作業、転記、定型文作成など、AIや自動化へ移管できる業務を見つける。

#### ログではなく、判断材料を届ける

管理画面の主役はスクリーンショット一覧ではなく、「何が起きているか」「なぜ重要か」「次に何をするか」が分かるレポートと提案である。

#### 根拠を追跡できる

AIの分類・集計・提案には、対象期間、対象人数、算出方法、信頼度、除外条件を表示する。必要な権限を持つ利用者だけが、集計根拠へ段階的にドリルダウンできる。

#### プライバシーを初期設計に含める

取得対象、取得停止、除外アプリ、保存期間、閲覧権限、利用目的、本人への説明を後付けにしない。

## 3. LPから導かれる管理画面の役割

管理画面には、次の4つの役割がある。

1. **経営判断:** AI化候補を削減可能時間とともに優先順位化する
2. **業務改善:** 部署・業務・期間ごとの時間配分と変化を把握する
3. **レポート配信:** 立場別の週次レポートを確認・確定・配信する
4. **安全な運用:** 従業員、端末、同意、収集状態、権限、保存期間を管理する

## 4. 想定ユーザーと権限

| ロール | 主な目的 | 閲覧範囲 |
|---|---|---|
| 本人 | 自分の振り返り、誤分類の訂正 | 自分の日報・集計・許可された記録 |
| マネージャー | チームの業務改善 | 担当組織の集計。個人詳細はポリシーで制御 |
| 経営者 | 全社傾向とAI投資判断 | 全社・部署別の集計とAI化提案 |
| 運用管理者 | 導入、配信、データ品質、端末管理 | 運用メタデータ。業務内容の閲覧は最小化 |
| セキュリティ／監査担当 | 利用状況と規程順守の確認 | 設定、同意、監査ログ。内容閲覧は原則不可 |

原則として、組織階層と担当範囲に基づくRBACを採用する。「管理者だからすべての画像を見られる」という設計にはしない。

## 5. 管理画面の情報設計

### 5.1 ナビゲーション案

- ホーム
- 業務分析
- AI化候補
- レポート
- 従業員・組織
- 端末・収集状況
- 分類ルール
- プライバシー・データ管理
- ユーザー・権限
- 監査ログ
- 組織設定

### 5.2 ホーム／経営ダッシュボード

表示する情報:

- 対象期間、対象人数、データ取得率、分析完了率
- 業務カテゴリ別の実測時間
- 前週・前月との増減
- AI化候補トップ3〜5
- 候補ごとの対象時間、削減可能時間、削減率、推奨施策
- 部署別の改善余地
- レポートの生成・確認・配信状況
- 端末停止、分析失敗、データ不足などの要対応事項

要件:

- 期間、部署、職種、雇用区分、業務カテゴリで絞り込める
- 集計の母数と取得率を常に併記する
- 個人ランキングを標準表示しない
- 前週比だけでなく、4〜12週のトレンドを確認できる
- AI化候補から根拠とアクションへ遷移できる

### 5.3 業務分析

- 業務カテゴリ別の総時間・構成比・一人当たり時間
- 部署別、職種別、曜日別、時間帯別の内訳
- 定型・反復業務、会議、コミュニケーション、顧客対応等の推移
- 集中作業やコンテキストスイッチの参考指標
- AI分類の信頼度と未分類時間
- 分類カテゴリから日単位・時間帯単位へドリルダウン
- CSV等での集計データ出力

個人単位の表示は、本人利用または明示的に許可された改善目的に限定する。低信頼度データは確定値と区別する。

### 5.4 AI化候補

候補ごとに以下を表示する。

- 対象業務と業務説明
- 対象部署・対象人数
- 現在の実測時間（週／月）
- 自動化可能割合と根拠
- 削減可能時間と金額換算（人件費設定がある場合）
- 実装難易度、リスク、導入コスト
- 推奨手段（AIツール、RPA、OCR、標準化、研修等）
- 算出式、前提、AI信頼度
- 根拠期間とサンプル量
- 推奨オーナーと次のアクション

候補のステータス:

`新規提案 → レビュー中 → 検証予定 → PoC中 → 導入済み → 効果測定 → 見送り`

候補を採用・見送りする際は、理由と判断者を残す。導入前後の時間を比較し、予測削減時間と実績の差を測定できるようにする。

### 5.5 レポート

#### レポート種別

- 本人向け日次レポート
- マネージャー向け週次レポート
- 経営向け週次／月次レポート
- AI化施策の効果測定レポート

#### レポート機能

- 生成中、レビュー待ち、確定、配信済み、失敗の状態管理
- AI生成文と数値根拠の同時表示
- 権限者による確認、編集、確定、再生成
- Web閲覧、PDF出力、メール等による配信
- 配信先と配信スケジュールの管理
- 数値・文章・対象期間・版の履歴保持
- 誤りを訂正して再配信した履歴の保持

AI文章を自動配信する場合も、導入初期は人の確認を必須にできる設定を用意する。

### 5.6 従業員・組織管理

- 従業員の登録、招待、停止、退職処理
- 部署・チーム・役職・上長関係の管理
- CSV一括登録・更新
- 対象者ごとの収集開始日、同意状態、ポリシー適用状態
- レポート配信先と閲覧範囲
- 異動時に過去データの閲覧範囲が不適切に広がらない制御

### 5.7 端末・収集状況

- 端末名、利用者、アプリバージョン、最終通信日時
- 稼働中、一時停止、オフライン、エラー、無効化の状態
- 取得予定数に対する取得率
- AI分析成功率、未分析件数、再処理状態
- 記録停止時間と停止理由
- 除外アプリ・URL・画面ロック・アイドル等の適用状況
- クライアント更新状況
- 障害の診断情報。ただし業務内容を不必要に露出しない

### 5.8 分類ルール・データ品質

- 業務カテゴリの作成、階層化、名称変更、廃止
- 部署・職種別の分類ルール
- 未分類・低信頼度データの確認
- 本人または許可されたレビュアーによる分類訂正
- 訂正履歴と、AI再学習・ルール改善への反映
- カテゴリ変更時の過去集計への影響確認
- 同一期間の再集計とバージョン管理

### 5.9 プライバシー・データ管理

- 収集目的と従業員向け説明文の管理
- 同意取得・撤回の記録
- 記録の一時停止と本人への状態表示
- 除外アプリ、除外URL、除外時間帯の設定
- パスワード、金融、医療、個人連絡等の機微情報を収集・表示しない仕組み
- スクリーンショット、抽出情報、日報、集計、監査ログ別の保存期間
- データ削除依頼、退職者データの処理、リーガルホールド
- テナント単位のデータエクスポートと削除
- 生画像を保存する場合の暗号化、アクセス制限、透かし、閲覧ログ

重要: 生のスクリーンショット閲覧はMVPの必須機能とはしない。必要性が認められる場合も、本人確認、誤分類調査等の限定用途・限定期間・限定権限とする。

### 5.10 ユーザー・権限・監査

- ロールと組織スコープによるアクセス制御
- SSO、MFA、セッション管理
- 権限付与・変更・失効
- レポート閲覧、出力、設定変更、画像閲覧、削除等の監査ログ
- 管理者自身の操作も監査対象とする
- 監査ログは内容本文を過剰に含めず、改ざん耐性を持たせる

## 6. 主要な業務フロー

### 6.1 導入

1. 組織、部署、管理者を登録する
2. 収集目的、対象、保存期間、除外設定を決める
3. 従業員向け説明と同意プロセスを完了する
4. 従業員と端末を登録し、アプリを配布する
5. テスト取得でデータ品質と除外設定を確認する
6. 本稼働を開始し、取得率を監視する

### 6.2 週次レポート

1. 週次集計を締める
2. データ不足、未分類、異常値を検査する
3. AIが対象別レポートとAI化候補を生成する
4. 権限者が数値根拠と文章をレビューする
5. レポートを確定し、対象者へ配信する
6. 閲覧・訂正・フィードバックを記録する

### 6.3 AI化施策

1. AI化候補を選択する
2. 削減見込み、難易度、リスクをレビューする
3. オーナー、対象範囲、検証期間、成功指標を設定する
4. PoCまたは施策を実施する
5. 導入前後の実測データを比較する
6. 継続、展開、見送りを判断し、結果を残す

## 7. 非機能要件

### 7.1 セキュリティ

- 通信時・保存時の暗号化
- テナント間の厳格なデータ分離
- 最小権限と組織スコープ制御
- 機微データのマスキングと収集除外
- 秘密情報を画面やログに平文表示しない
- 脆弱性対応、依存関係更新、インシデント記録

### 7.2 可用性・運用性

- 取得、アップロード、分析、レポート生成の各段階を監視可能にする
- 一時的なオフラインや分析失敗から安全に再送・再処理できる
- 同一データの二重計上を防ぐ
- 障害時にも既存データを消さず、状態と復旧手段を示す

### 7.3 性能・拡張性

- ダッシュボードの主要集計は通常条件で数秒以内に表示する
- 大規模組織では集計済みデータを利用し、生ログ全走査を避ける
- 長期間・多人数でも期間と組織による絞り込みが安定して動作する

### 7.4 説明可能性

- AI分類とAI化提案に信頼度、根拠、前提条件を表示する
- 推定値と実測値を明確に区別する
- AIモデル、プロンプト、分類ルールの変更による数値差を追跡できる
- 人が訂正・却下でき、その履歴を保持する

### 7.5 アクセシビリティ・表示

- 色だけに依存せず状態を伝える
- キーボード操作、十分なコントラスト、適切なラベルを備える
- 日本語を第一言語とし、日時・週の境界・タイムゾーンを組織設定に従う

## 8. MVPの推奨範囲

### Must

- 管理者ログインと基本的なアクセス制御
- 確定済み週次レポートの一覧・詳細表示
- 部署、対象期間、従業員名による絞り込み
- 業務カテゴリ別の実測時間
- AI化候補、削減可能時間、提案理由の表示
- 対象人数、取得率、未分類率などデータ品質の表示
- 従業員・端末の登録状態と最終同期状態
- レポートの生成・確定・配信状態
- 操作監査ログ
- 保存期間と削除の基本設定

### Should

- 部署別・期間別トレンド
- レポートのPDF／CSV出力
- レポートのレビュー・確定フロー
- 分類訂正と履歴
- AI化候補のステータス管理
- SSO／MFA
- 除外アプリ・時間帯のポリシー管理

### Later

- AI化施策の案件管理と導入前後比較
- 高度なコスト・ROIシミュレーション
- HRマスターやIDプロバイダーとの自動同期
- Slack、Teams、メール等への配信連携
- 組織独自カテゴリへの継続学習
- 複数国・複数言語・データレジデンシー対応

## 9. 既存POCとの境界

既存仕様では、管理画面へ送信・表示する対象を**確定済みの管理者向け週次レポート**に限定している。本人日報、スクリーンショット、詳細な作業ログを管理サーバーへ送るAPIは持たない。

したがって、現在の管理画面で優先すべきものは以下である。

- 週次レポートの一覧、検索、詳細閲覧
- レポートに含まれる集計とAI化候補の分かりやすい表示
- 同期状態、対象端末、対象部署、対象人数の確認
- 認証、暗号化、監査、保存期限

スクリーンショット閲覧、本人日報閲覧、リアルタイム個人監視は、LPの価値提供に必須ではなく、現行のプライバシー境界にも反するため対象外とする。将来必要になった場合は、利用目的、法務、従業員説明、同意、RBAC、保存期間を別途承認したうえで仕様化する。

## 10. 成功指標

### プロダクト価値

- 自動日報の閲覧率・訂正率
- 週次レポートの閲覧率
- 未分類時間の割合
- AI化候補のレビュー率・採用率
- 提案からPoC開始までの日数
- 施策による実測削減時間
- 予測削減時間と実績の差

### 運用品質

- 対象端末の正常取得率
- 分析成功率と処理遅延
- レポートの定刻生成・配信率
- 権限・プライバシーに関する問い合わせ件数
- データ削除依頼の期限内完了率

個人の稼働時間の多寡や「生産性ランキング」は、標準KPIにしない。

## 11. 未決事項

- スクリーンショットをサーバーへ送るか、端末内解析にするか
- 生画像、抽出ログ、集計、レポートそれぞれの正式な保存期間
- マネージャーが個人別データを閲覧できる条件
- 本人による分類訂正の確定権限と集計への反映タイミング
- AI化可能割合と削減時間の標準算出方法
- 人件費を用いた金額換算を表示するか
- レポートを自動配信するか、毎回人が確定するか
- 同意の法的根拠と、就業規則・労使協議を含む導入手順
- 正式価格、初期費用、最低利用人数、契約単位
- 申込フォームと問い合わせ導線
- LP掲載の市場データについて、公開時点での出典・日付・数値の最終確認

## 12. 受け入れ条件の例

- 経営者が、今週のAI化候補トップ3と各候補の削減可能時間を3クリック以内で確認できる
- 表示するすべての集計に、対象期間、対象人数、取得率が示される
- 権限のないユーザーは、別部署や個人のデータへURL直打ちでもアクセスできない
- AI生成の提案から、算出根拠と対象データの範囲を確認できる
- レポートの確定・編集・配信・出力が監査ログに残る
- 端末や分析の欠損がある場合、正常な確定値に見せず警告する
- 保存期限を迎えたデータはポリシーどおり削除され、削除結果を監査できる
- 標準状態では、生スクリーンショットや個人ランキングが管理者画面に表示されない
