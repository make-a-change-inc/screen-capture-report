# Report Viewer and Management Sync MVP v1

この仕様は2026-07-20のGPT-5.6 SolによるGrill-me代替レビューで確定した。
既存のWindows POCを拡張しつつ、画面画像と本人日報を端末外へ出さない境界を維持する。

## データ境界

| データ | 従業員アプリ | 管理Web | 既定保持 |
|---|---:|---:|---:|
| キャプチャ画像 | 復号表示可 | 送信・表示不可 | 最大24時間 |
| 本人日報 `daily / employee` | 復号表示可 | 送信・表示不可 | 90日 |
| 管理者向け週次 `weekly / management` | 共有前プレビュー可 | 閲覧可 | 端末・サーバー90日 |
| 内容を含まない監査ログ | 状態表示 | 閲覧可 | サーバー365日 |

- 端末の既存Fernet暗号とDPAPI CurrentUser鍵を変更しない。
- 復号済みHTML・PNGはアプリのメモリ内だけで表示し、平文一時ファイルを作らない。
- 管理Webに画像、本人日報、ウィンドウタイトルを受け付けるAPIを作らない。
- AI生成HTMLはスクリプト権限なしのsandbox iframeと厳格なCSPで表示する。

## 同意

既存の`windows-poc-v2`同意をサーバー送信の根拠に流用しない。
管理Web同期は別の`server-sync-v1`明示同意が必要で、未同意時はネットワーク送信を行わない。
同意画面には送信する項目、送信しない項目、送信先、停止方法を表示する。

## 構成

第一案はSites Worker + D1一体構成だったが、SitesのWorkerデプロイが静的`dist`成果物契約で
2回失敗したため、公開スキルの再試行上限に従いCloudflare Workers + D1へ切り替える。

```text
Windows app -- HTTPS + device Bearer --> Cloudflare Worker --> D1
                                                |
                                                +--> owner/admin dashboard
```

- レポート本文はWorkerでAES-256-GCM暗号化してD1へ保存する。
- 暗号鍵と管理APIハッシュはWorker Secretに置く。
- 端末トークンは256bit乱数とし、D1にはSHA-256だけを保存する。
- 管理APIは管理キーを追加検証し、端末トークンでは利用できない。
- `report_id`をIdempotency-Keyとして重複送信を防ぐ。
- 90日を超えたレポートとメトリクスはCronで削除し、監査イベントを残す。

## UI

従業員アプリの「レポートと画像を見る」は次を提供する。

- 日付別の本人日報
- 保持中キャプチャの時刻一覧と画像プレビュー
- 管理者に共有される週次レポートの本文、確定状態、同期状態
- 復号・破損エラーの明示。失敗時に既存データを削除しない

管理Webは次を提供する。

- 登録従業員、週次レポート、同期端末、部署数の概要
- 氏名・部署によるレポート絞り込み
- 週次レポート詳細と送信内容SHA-256
- 従業員・端末の登録と、一度だけ表示する端末トークン
- 本人日報・画像が管理Webへ送られないことの常時表示

## 受入条件

1. 既存DPAPI/Fernetデータの本人日報、週次管理レポート、PNGを新UIで閲覧できる。
2. 復号後も平文HTML・PNGをディスクへ残さない。
3. 鍵破損や別ユーザーでは安全に失敗し、既存データを削除しない。
4. `server-sync-v1`未同意では送信が0件である。
5. 同意後も確定済み`weekly / management`だけを送信する。
6. 本人日報または画像を送るAPI・コードパスが存在しない。
7. 同じIdempotency-Keyで重複行を作らない。
8. サーバー保存前に本文を暗号化し、表示時SHA-256が送信内容と一致する。
9. 未認証管理API、無効端末token、別端末への成りすましを拒否する。
10. レポート内のscriptや外部通信をsandbox/CSPで実行しない。
11. 90日超のサーバーレポートを削除し、内容を含まない監査記録を残す。
12. 本番URLで端末登録、合成週次送信、管理者閲覧のE2Eが成功する。
